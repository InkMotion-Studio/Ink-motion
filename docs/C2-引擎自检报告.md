## 2. M1 闸门三大技术风险验证（IM-PLAN-001 §6）

### 风险 1：Hanzi Writer 覆盖率与打包体积
- **验证方式：** 逐字从 CDN 按需加载 `hanzi-writer-data`，缺失/超时返回 `null` 并触发整字降级。
- **结论：** ✅ 通过。逐字懒加载避免整包体积；降级路径经场景编排验证不崩溃（`drawSongGlyph` 承接）。
- **遗留：** 需在 C4 抽样统计常用诗文覆盖率，量化降级率（记入 IM-TEST-001 §5.4）。

### 风险 2：骨架化质量
- **结论：** ⏸ 未验证（**阻塞**）。依赖开源小篆字库发布（IM-RISK-001 R-01）；已按计划推迟至 V1.0。
- **处置：** UI 层显式禁用古文字选项并标注阻塞原因；引擎层 `isBlockedPath` 守卫跳过。符合"调范围"机制。

### 风险 3：WebCodecs H.264 / MediaRecorder WebM
- **验证方式：** `detectCapabilities()` 运行时探测 `VideoEncoder`（WebCodecs）与 `MediaRecorder.isTypeSupported`。
- **决策矩阵落地：**
  - 有 WebCodecs → 首选 MP4（`avc1.4d0028` Main 4.0，适配 1080×1920），编码失败自动降级 WebM。
  - 无 WebCodecs（如 Firefox 全系）→ WebM（VP9→VP8→默认）保底。
  - 两者皆无 → 明确报错，不静默失败。
- **结论：** ✅ 逻辑通过（Node 侧能力分支与导出流程可执行）；**真机编码结果需用户在本地浏览器实测**。
