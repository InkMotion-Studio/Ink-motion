# InkMotion V2-C7 · 汉字书写笔顺内置与逐笔动画 · 落地计划（修订版）

> 修订说明：原 C1–C5 计划以 hanzi-writer（第三方标注数据）为主线，经用户指正后推翻。
> 正确路线：**笔顺是公开确定性规范（非需标注/学习的神秘数据），应内置权威笔顺表 + 用户定制兜底，运笔轨迹由字体轮廓实时生成。彻底脱离任何单一老外项目。**
> 文档驱动 + 检查点交付：每检查点打包可运行 zip，用户回复「通过」后进入下一点。

## 0. 核心认知（用户定调）

> 不要在单一外部项目上纠结。汉字笔顺是确定性规范，直接内置新华字典/通用规范汉字表级数据源即可。
> **A+B+C 三层并用、以用户定制兜底才是正道**：
> - **A（主层·权威规范）**：内置《通用规范汉字表》8105 字笔顺，默认底座，覆盖 99% 现代文本，体积最小、零外部依赖。
> - **B（增强层·新华字典级）**：扩展到新华字表/通用字更全面覆盖，补 A 未含的生僻字、异体字、地名用字。
> - **C（兜底层·用户定制）**：用户可上传/编辑任意字笔顺（书法体特殊笔顺、甲骨金文、自造字），运行时按「用户定制 > B > A」优先级查表；查不到才走字体轮廓实时近似。

## 2. 三层笔顺数据架构

```
优先级查表（运行时）：
  用户定制表(C, IndexedDB/导入)  → 命中即用
  B 层（新华字典级全量）         → 命中即用
  A 层（通用规范汉字表 8105）     → 命中即用
  字体轮廓实时近似(outline.ts)   → 最终兜底（无笔顺数据时的可接受降级）
```

- **数据形态**：每字 = `{ strokes: number[]（笔顺：笔画类型序列/笔画索引序列）, count: number, radical?: string }`。纯文本/JSON，体积极轻（8105 字 ≈ 数百 KB，远小于几 MB 的公式 JSON）。
- **脱离 hanzi-writer**：不再 `fetch(HW_CDN + char + '.json')`；`HW_CDN` 常量、`hanzi-writer` 依赖从 `stroke.ts` / `fonts.ts` / `licenses.ts` 移除。
- **坐标约定**：运笔轨迹在运行期由 `outline.ts` 取该字 glyph 轮廓，按笔顺表切分笔画段 → 每段生成中线/路径。**笔顺（顺序）来自规范表，形态（轨迹）来自字体轮廓**，二者解耦、对任意字体普适。

## 3. 落地拆解（C1–C6 检查点）

### C1 · 笔顺数据源内置（A+B 层）
- 获取并内置两份公开权威笔顺数据：
  - **A**：《通用规范汉字表》8105 字笔顺（GF 3002 规范衍生公开数据集）。
  - **B**：新华字典/通用字更全面笔顺覆盖（补生僻/异体/地名用字）。
- 统一为 `{ char → strokes[] }` 结构，构建期生成 `public/strokeorder/<layer>.json`（可按码段分片，按需加载，不进首屏）。
- 编写 `scripts/build-strokeorder.mjs`：合并 A/B、去重、校验（笔画数自洽、字符为 CJK）。
- **交付判定**：`--check` 通过；A 层覆盖 8105 字、B 层覆盖差集；抽样 50 字笔顺与规范一致。

### C2 · 运行时三层查表 + 脱离 CDN（根除 BUG-003）
- 重写 `src/engine/stroke.ts`：删除 `HW_CDN`/fetch；新增 `getStrokeOrder(char)`：
  - 按「C(IndexedDB) > B > A」查表；全缺失 → 返回 `null` 走轮廓兜底。
  - 公式资产**本地按需加载**（动态 import + 缓存 Map），**0 网络请求**。
- 改造 `src/engine/scene.ts:154-163` 预加载循环：仅对 CJK 且本地有数据的字请求公式；其余走整字/兜底。
- **交付判定**：真实浏览器验证——输入含标点/数字/字母/生僻字文本，控制台 **0 个 404**；楷/宋/仿宋三体逐笔正常。

### C3 · 轮廓兜底引擎（outline.ts 切分笔画）
- 实现 `buildStrokePaths(char, fontStack)`：用 `outline.ts` 取 glyph 轮廓 → 按 C2 笔顺序列切分笔画段 → 每段生成中线点序列（形态学骨架/最大内切圆近似）→ 输出可动画的 path。
- 未知字/无笔顺字：用整体轮廓描边兜底（双钩描红观感），不阻塞主线。
- **交付判定**：抽样 30 字（含 A/B 命中与兜底字）动画轨迹合理、笔顺与字形一致（人工目视）。

### C4 · 用户定制兜底层（C 层）
- 新增「笔顺编辑/导入」能力：用户可为任意字录入/修改笔顺（书法体、甲骨金文、自造字）。
- 存储于 IndexedDB，运行时最高优先级查表；支持导出/导入自定义笔顺 JSON（复用 V2-C4 导入闭环）。
- **交付判定**：录入一字 → 该字在所有字体下按用户笔顺逐笔；导出/导入往返一致。

### C5 · 书写引擎统一与观感
- 抽象 `DrawGlyph`：三体统一「笔顺查表 → 逐笔 SVG 描边 + 填充渐显」；保留 C3 兜底。
- 笔触观感（起收笔方向由笔顺序列推出 `strokeType`，叠加笔锋/墨渗参数）。
- **交付判定**：三体逐笔在竖排布局下正确；四断点响应式正常。

### C6 · 载体体系重构（承接方法论 V2-C7 第四节）
- 扩为 8–10 种实体中国传统形制（宣纸/绢帛/信笺/洒金笺/竹简/木牍/碑拓/金文/立轴/手卷/团扇/册页/屏风），多层程序化材质合成，去廉价平铺；暴露类型/色温/装裱边/钤印位参数。
- **交付判定**：四断点正确；8–10 种载体预览无平涂感（截图对比 V2-C5 旧载体）。

### C7 · 整合回归 + 发布检查单（含 V2-C6 缺陷修复）
- 修复 V2-C6 全部 P1：BUG-001（暂停失效，缓动重绘 effect 加 `playing` 依赖）、BUG-002（编辑自动保存：debounce + 路由离开拦截）、BUG-003（C2 已根除）。
- 门禁全绿：`tsc` / `vitest` / `lint` / `build`（主包 gzip < 200KB，笔顺数据不进首屏）/ `check-i18n` / `e2e/all` / `e2e/release-check`。
- 新增 E2E：含标点/数字/中英混排真实样本，断言无 404、逐笔触发、编辑自动保存、用户定制笔顺生效。
- **交付判定**：发布检查单全绿；打包可运行 zip。
