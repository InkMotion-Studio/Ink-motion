## 2. 本文件与 IM-RISK-001 的关系

IM-RISK-001 是 **MVP 全周期**风险登记册，其 R-01~R-12 已随 MVP 交付完成闭环。本文件：

1. **承接** IM-RISK-001 中由 V1.0 继承的风险（R-02/R-04/R-05/R-06/R-10），更新其状态；
2. **关闭/降级**因外部依赖变化而失效的风险（R-01、R-03）；
3. **新增** V1.0 特有风险（VR-01~VR-10）；
4. **重绘** V1.0 风险矩阵与跟踪机制。

> 编号规则：MVP 风险沿用 `R-xx` 编号并在本文件标注状态；V1.0 新增风险使用 `VR-xx`，避免与既有编号冲突。

## 5. V1.0 新增风险登记册

### VR-01 篆书字库覆盖率不足 `[资产/产品·中]`

| 项 | 内容 |
|---|---|
| 描述 | 主字源仅 165 字，覆盖古诗/自由输入能力有限；用户输入大量越界字符会导致体验割裂 |
| 影响 | 古文字路径"可用但不好用"，功能卖点打折 |
| 概率 | 高（125 字级字库的客观事实） |
| 应对 | ① 分层字源策略（L0/L1/L2，IM-GLYPH-001 §6.2），默认接入 L0+L1（覆盖《道德经》《小学必背古诗》题材）；② 字表 UI 透明展示可用字数与内容包；③ 越界提示引导用户"改用楷/宋"或"仅保留在库字"；④ 提供高频古文字表预设文本，降低用户踩坑概率 |
| 触发条件 | 抽样覆盖率低于预期（GV-06 正确率/覆盖率不达） |
| 负责人 | 技术负责人 + 产品 |
| 跟踪 | V1-C1 抽样实测、V1-C4 验收 |

### VR-02 字库可持续性（霞鹜篆书停止维护）`[资产·高]`

| 项 | 内容 |
|---|---|
| 描述 | 霞鹜篆书**正式版完成后不再维护**（已声明），字库长期无更新；若出现缺字/错误，无上游修复 |
| 影响 | 长期字形质量与覆盖率的提升通道受限 |
| 概率 | 高（已声明事实） |
| 应对 | ① **架构解耦**：渲染层不绑定单一字体文件，字表与字体通过 `SealGlyph.source` / `fontFile` 间接引用（IM-GLYPH-001 §4.1）；② 保留备选字源接入位（敬峰、全字库）并**至少完成一款接入验证（GV-05）**；③ 字表版本化，允许后续替换字源而接口不变；④ 在帮助页说明字库现状，管理用户预期 |
| 触发条件 | 出现必须修复的缺字/错字且上游无响应 |
| 负责人 | 技术负责人 |
| 跟踪 | 每迭代复核；V1-C1 完成解耦验证 |

### VR-03 篆书子集化与体积控制 `[技术/质量·中]`

| 项 | 内容 |
|---|---|
| 描述 | 字体文件若不子集化，体积可能达数 MB；子集化过度又可能导致后续扩充时需重做 |
| 影响 | 首屏/按需加载超预算，或字表扩充返工 |
| 概率 | 中 |
| 应对 | ① 按**字表版本**生成子集（构建期一次性），字表变更即重新构建；② L0 用 woff2 子集化并计入首屏预算边缘；L1/L2 独立文件按需下载；③ 子集化后必须回归渲染测试（GV-04），确保无字形丢失 |
| 触发条件 | 字体资产超发布检查单 V1-C10 预算 |
| 负责人 | 前端架构 |
| 跟踪 | N4.3 性能优化 |

### VR-04 字体上传的安全与生命周期 `[技术/合规·中]`

| 项 | 内容 |
|---|---|
| 描述 | 用户上传任意字体文件：① 文件可能异常/超大导致解析崩溃或内存溢出；② 用户可能上传**无权使用**的商业字体，法律责任边界需明确；③ 字体存 IndexedDB 的生命周期（替换/删除/清理）需完备 |
| 影响 | 崩溃、隐私/合规争议、存储泄漏 |
| 概率 | 中 |
| 应对 | ① 大小上限（建议 ≤20MB）+ 类型白名单（.ttf/.otf/.woff2）+ 解析失败友好报错；② **纯本地存储，绝不上传**（列入发布检查单 V1-C1 零上传回归）；③ 上传时**强制用户确认"我确认拥有该字体使用权"**，并在字体列表标注"用户提供"；④ 提供删除与"清空用户字体"入口；⑤ 字体仅在本地注册 FontFace，刷新后可恢复 |
| 触发条件 | V1-C3 字体上传功能落地 |
| 负责人 | 前端架构 + 技术负责人 |
| 跟踪 | N3.1/N3.2、V1-C7 |

### VR-05 i18n 引入的回归与硬编码残留 `[质量·中]`

| 项 | 内容 |
|---|---|
| 描述 | 文案抽取过程易遗漏（硬编码残留）；语言切换可能导致路由/状态重置；英文文案长度差异破坏布局 |
| 影响 | 双语体验不完整，或 UI 破版 |
| 概率 | 中 |
| 应对 | ① 建立**硬编码扫描**（发布检查单 V1-C6）；② 文案抽取后逐屏走查；③ 英文文案在关键按钮/标签处做长度适配（允许换行/缩略）；④ 语言偏好持久化（IM-DB-001 settings） |
| 触发条件 | V1-C2 i18n 落地 |
| 负责人 | 前端架构 |
| 跟踪 | N2.2、N4.1、V1-C6 |

### VR-06 4K 导出的内存与编码压力 `[技术/质量·中]`

| 项 | 内容 |
|---|---|
| 描述 | 2160×3840 画布帧缓冲约为 1080P 的 4 倍，WebCodecs 编码内存与耗时显著上升，低配设备可能 OOM 或超时 |
| 影响 | 导出崩溃或长时间无响应，用户体验灾难 |
| 概率 | 中（低配设备上更高） |
| 应对 | ① 导出前做**能力探测**（`VideoEncoder.isConfigSupported` 检查分辨率/码率支持）；② 不支持则**明确降级到 1080P** 并提示原因，而非拒绝；③ 分块编码 + 及时释放帧；④ 导出队列中限制并发为 1；⑤ 列入 IM-TEST-V1 §5.8 与发布检查单 V1-C8 |
| 触发条件 | V1-C3 4K 规格落地 |
| 负责人 | 导出引擎负责人 |
| 跟踪 | N3.3、N4.3、V1-C8 |

### VR-07 导出队列的并发与状态一致性 `[技术·中]`

| 项 | 内容 |
|---|---|
| 描述 | 多任务导出涉及并发控制、取消、失败重试，状态机易出错（如任务卡在"导出中"、取消后仍写入 exports 表） |
| 影响 | 数据不一致、用户困惑 |
| 概率 | 中 |
| 应对 | ① 队列**串行执行**（并发 1），避免资源争抢；② 任务状态显式建模（queued/running/cancelled/failed/done）并持久化到 exports 表；③ 取消/失败必须清理 Blob 与中间状态（沿用 MVP TC-EXP-05 断言）；④ 刷新后恢复"未完成"任务为可重试态 |
| 触发条件 | V1-C3 导出队列落地 |
| 负责人 | 导出引擎负责人 |
| 跟踪 | N3.4、N4.1 |

### VR-08 深色主题对比度与载体视觉冲突 `[质量·UI·中]`

| 项 | 内容 |
|---|---|

| 应对 | ① 深色下重跑 axe-core 对比度审计（发布检查单 V1-C5）；② 明确"深色主题仅影响 UI 外壳，画布内容不受影响"的设计边界，并在帮助页说明；③ 若确需深色画布背景，作为独立选项评估（V1.1+），V1.0 不做 |
| 触发条件 | V1-C2 深色主题落地 |
| 负责人 | UI + 前端 |
| 跟踪 | N2.1、N4.4、V1-C5 |
