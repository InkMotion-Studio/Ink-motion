## 2. 引言

### 2.1 编写目的

本文档定义"墨演 InkMotion"的**开发计划与排期**，是项目从"规格设计"转入"工程落地"的总控文档。它承接 8 份已批准设计文档与《IM-BASELINE-001 可执行基线修正版》，并引用同步产出的《IM-RISK-001 风险管理计划》《IM-TEST-001 测试计划》《IM-OPS-001 部署与运维文档》。

### 2.2 范围

- **在范围内**：MVP / V1.0 / V2.0 三阶段的功能落地、工程排期、依赖与里程碑、质量门禁、发布检查单。
- **不在范围内**：具体代码实现（由后续逐节点执行产出）；商业运营与变现（纯前端、无账号/订阅/支付，见 IM-PRD-001 §5.2、IM-DB-001 §3.3）。

### 2.3 关键约束（来自基线，不可逾越）

| 约束 | 内容 | 来源 |
|---|---|---|
| 纯前端 | 无服务端数据库、无 HTTP API、无账号系统 | IM-ARCH-001 AC-01、IM-API-001 §2.2 |
| 渲染分期 | Canvas2D 为 MVP/V1.0；Three.js/WebGL 为 V2.0 | IM-BASELINE-001 |
| 笔画三路径 | 楷体=hanzi-writer 精确；宋体=whole 整字；古文字=skeleton 骨架化 | IM-TECH-001 §7.1、IM-BASELINE-001 |
| 古文字受限字库 | 仅预设字符集，非任意文本；开源小篆尚未发布 | IM-BASELINE-001、IM-DB-001 §6.3 |
| 许可合规 | Arphic PL 须可见署名；开源小篆 OFL 须署名且待发布 | IM-API-001 §5.1、IM-UI-001 §6.5.1 |
| 字数上限 | 文本 ≤ 5000 字（硬上限） | IM-SRS-001 §3.5、IM-DB-001 DC-06 |

## 3. 交付范围定义（MVP / V1.0 / V2.0）

> **本计划最重要的基线：先界定"完成"的边界，再排期。**

### 3.1 MVP（最小可发布集）

| 维度 | 范围 |
|---|---|
| 字体 | 楷体（Arphic UKai，精确笔顺）+ 宋体（Source Han Serif，整字显现） |
| 载体 | 宣纸卷轴、竹简（Canvas2D 贴图） |
| 导出 | **WebM（MediaRecorder）保底先行**；MP4（WebCodecs H.264）作为增强，可用时自动启用 |
| 页面 | 首页、编辑器（三栏）、我的项目、设置 |
| 隐私 | 零上传（用户文本/项目/字体仅本地）；隐私声明 |
| 合规 | Arphic PL 可见署名（关于/致谢页） |
| 主题 | 仅浅色 |
| 语言 | 仅中文 |
| 平台 | 桌面 Chromium / Safari 26+ 为主；Firefox 全系走 WebM |

### 3.2 V1.0（MVP 之后）

古文字路径（小篆/隶书骨架化，**依赖字体资产就绪**）、模板库页、帮助页、深色主题、英文 i18n、字体上传（用户字体）、4K 导出（阶段待定，见 IM-DB-001 R5/IM-API-001 R2）、字体市场前瞻（registerFont）。

### 3.3 V2.0（远期）

金文/甲骨文（受限字库）、Three.js/WebGL 3D 载体（甲骨/青铜/石碑）、透明背景（ffmpeg.wasm）、匿名埋点（需授权）、插件市场（PluginLoader）、SDF 缓存。

## 6. 技术风险闸门（M1 引擎 Demo 前必须验证）

> 对应评审异议 A4 与补充建议。N2.2/N2.3/N2.6 是工作量与成败最不可预测的三块，必须在 **M1（阶段 2 末）** 前用时间盒 Spike 验证：

1. **Hanzi Writer 覆盖率与打包体积**：抽样验证常用诗词/古文覆盖率；测逐字 stroke JSON 体积；确认缺失字"整字显现"降级在 MVP 可用。
2. **骨架化质量**：小篆/隶书位图跑 MAT/Zhang-Suen+RDP，肉眼评估笔锋路径是否可用（R&D 风险）。
3. **WebCodecs H.264 从 canvas 编码**在目标浏览器跑通；确认 MediaRecorder WebM 全浏览器保底。

若任一不过关，立即调范围（古文字推 V2.0 / MVP 仅 WebM），不进入阶段 3。
