# InkMotion 全功能逐项自测 · Bug 清单（V2-C6）

**测试版本**：InkMotion V2.0（V2-C5 交付物）
**测试日期**：2026-10-14
**测试环境**：Chromium stable（`chromium-1208`）· viewport 1440×900 · preview 构建（`localhost:4173`）
**测试范围**：96 项用例 / 5 个批次（页面导航 · 编辑器核心交互 · 项目与字体管理 · 导出与无障碍 · i18n 与性能与异常恢复）
**总体结果**：**96 项中 88 项通过，检出 6 项真实缺陷**（另有 5 项初判「失败」经逐项复核确认为**脚本误报**，不计入缺陷）

> 复现方式：所有缺陷均可用 `npm run preview` 后按「复现步骤」在浏览器中手动重现；证据栏为真实浏览器运行时读数。

## 二、缺陷详情

### 🔴 BUG-001 — 预览暂停失效

| 项 | 内容 |
|---|---|
| **严重度** | P1（核心动效不可控） |
| **模块** | `src/components/PreviewCanvas.tsx` |
| **复现步骤** | 1. 新建作品，输入任意文本<br>2. 等待预览开始自动播放<br>3. 点击预览控制条「暂停」按钮<br>4. 观察按钮文案与进度条 |
| **预期** | 按钮变为「播放」，进度条停在当前百分比不动 |
| **实际** | 按钮**确实**变为「播放」，但进度条继续推进（证明状态已置为暂停，但渲染循环未停） |
| **证据** | `暂停前:21% → t+1s:32% / 点击后按钮=播放 / 暂停后进度: 30% → 41% → 52%`（三次采样仍在匀速前进） |
| **根因** | `PreviewCanvas` 内**两套 rAF 并存且互不知情**：<br>① 播放循环 `useEffect`（依赖 `[playing, project.options, project.text]`，受 `playing` 控制）；<br>② V2-C5 新增的「缓动重绘」`useEffect`（依赖 `[project.id, project.text, project.options]`，**不含 `playing`**，位于第 158–178 行）。<br>暂停只切断 ①，② 的单帧重绘链仍在推进 `progressRef`，于是画面继续演进。 |
| **影响面** | 所有用户、所有字体路径；V2-C5 交付的「参数变化可观测」修复引入了该回归 |

### 🔴 BUG-002 — 编辑无自动保存，离开即丢失

| 项 | 内容 |
|---|---|
| **严重度** | P1（**数据丢失**，最高优先） |
| **模块** | `src/pages/Editor.tsx` · `src/store/editor.ts` |
| **复现步骤** | 1. 新建作品<br>2. 在左侧「正文」输入 `静夜思 李白 床前明月光`<br>3. **不点**工具栏「保存」，直接点「返回」回到项目列表<br>4. 观察该作品卡片副标题 |
| **预期** | 正文与标题应随输入自动落库（或离开时拦截提示「有未保存修改」） |
| **实际** | 卡片副标题恒为「（空）」；重新打开该作品，正文为**空字符串**。刷新后依然为空（数据从未写入） |
| **证据** | `A) 不刷新回列表卡片: "新建作品 （空）" / B) 重新打开 textarea 值: "" / C) 刷新后 textarea 值: ""`<br>对照：改标题后不保存返回，卡片仍为「新建作品」——`标题已持久化: NO`<br>对照：显式 `Ctrl+S` 后，卡片正确显示 `持久化测试甲乙丙丁`，参数（字体=song）也能保持——说明**只有「保存」动作会落库** |
| **根因** | `useEditorStore` 的 `setText/setTitle/setOptions` 只更新内存 state 并置 `dirty=true`，**没有任何持久化**；项目无自动保存（无 debounce 写库、无 `beforeunload`/`pagehide`/路由离开拦截）。`save()` 仅在用户点击「保存」按钮或 `Ctrl+S` 时被调用。 |
| **影响面** | 所有用户；这是最容易被普通用户踩到的路径（编辑完直接返回） |

### 🔴 BUG-003 — 笔顺数据对非 CJK 字符无条件请求（404 泛洪）

| 项 | 内容 |
|---|---|
| **严重度** | P1（**默认路径即可触发**，控制台污染 + 无谓网络请求） |
| **模块** | `src/engine/scene.ts` 第 154–163 行 · `src/engine/stroke.ts` `loadStrokeData()` |
| **复现步骤** | 1. 新建作品（保持默认楷体）<br>2. 输入 `床前明月光，疑是地上霜。`（含中文标点）<br>3. 打开 DevTools → Network，筛选 404 |
| **预期** | 仅对真实存在笔顺数据的 CJK 汉字发起请求；标点/数字/字母应跳过或走本地降级 |
| **实际** | 对**每个字符**（含标点、数字、字母、甚至非 BMP 生僻字）一律请求 `https://cdn.jsdelivr.net/npm/hanzi-writer-data@2.0.1/<char>.json`，不存在即返回 404 |
| **证据** | 楷体+标点：`404 。.json`、`404 ，.json`（2 条）<br>楷体+数字字母：`404 1.json / 2.json / 3.json / A.json / B.json / C.json`（6 条）<br>篆书+生僻字：`404 %F0%BF%AE%AE.json` 等 8 条<br>项目列表/设置页亦可见 3 条 404（同源） |
| **根因** | `scene.ts` 预加载循环 `chars = [...new Set(glyphs.map(g => g.char))].filter(c => c.trim() && !data.has(c))` —— **既无 CJK 码位范围过滤，也无 `fontFamily==='kai'` 守卫**，故对任意字符都调 `loadStrokeData()`。`loadStrokeData()` 内部虽有 `try/catch` 降级（返回 `null`），但网络层的 404 已产生。 |
| **影响面** | 所有含标点/数字/字母的文本（即绝大多数真实作品）；虽不致功能崩溃，但属明确的资源浪费与可观测缺陷 |
| **建议** | 在预加载前加 CJK 判定（如 `cp >= 0x4E00 && cp <= 0x9FFF` 或扩展 A/B 白名单），并仅当 `fontFamily==='kai'` 时才预加载 |

### 🟠 BUG-004 — 关于页「开源组件」说明硬编码中文

| 项 | 内容 |
|---|---|
| **严重度** | P2（i18n 覆盖缺口） |
| **模块** | `src/lib/licenses.ts`（第 125、157 行等，共 16 处 `usage:` 字段）→ `src/pages/About.tsx` 第 185 行渲染 |
| **复现步骤** | 1. 设置页切换语言为 English<br>2. 打开「关于 / About」页<br>3. 查看「Open-Source Components」区块每条的说明文字 |
| **预期** | 说明文字随语言切换为英文 |
| **实际** | 说明文字恒为中文，例如 `— IndexedDB 封装（项目/设置/字体本地持久化）`、`— MP4 封装（WebCodecs 导出路径）` |
| **证据** | 英文模式 About 页仍检出中文串：`封装 / 项目 / 设置`（`usage` 字段），页面其余部分（标题、许可说明）已正确英译 |
| **根因** | `licenses.ts` 是 TS 数据文件，其 `usage` 为中文字面量且**直接渲染**，未走 `t()`。而 `scripts/check-i18n.mjs` 的 `SCAN_DIRS = ['src/pages', 'src/components']` **未覆盖 `src/lib`**，因此该硬编码逃过了 i18n 门禁。 |
| **影响面** | 英文用户；同时暴露「i18n 校验范围不足」的流程缺陷 |
| **建议** | 将 `usage` 改为 `usageKey` 走 i18n 字典，并把 `src/lib`（数据文件）纳入 `check-i18n.mjs` 扫描 |

### 🟠 BUG-005 — 纯生僻字静默无输出

| 项 | 内容 |
|---|---|
| **严重度** | P2（缺输出 + 缺提示 = 用户无从判断） |
| **模块** | 渲染层（篆书/宋体整字路径）+ 编辑器提示 |
| **复现步骤** | 1. 新建作品<br>2. 仅输入 CJK 扩展 B 区字符，如 `𠀀𠀁𠀂`<br>3. 观察预览画布与提示区 |
| **预期** | 要么渲染出来（若字体覆盖），要么明确提示「以下字符当前字体不支持」(同篆书越界提示机制) |
| **实际** | 画布 `ink = 0`（**完全空白**），且无任何提示文字；用户无法区分「没渲染」与「坏了」 |
| **证据** | `扩展B区纯生僻字 ink = 0`；对照 `永𠀀 ink = 1685`（混入常用字时有输出）——证明是**该字本身无渲染**而非画布故障 |
| **根因** | 整字渲染路径依赖字体覆盖字形；系统字体对扩展 B 区无覆盖时 `fillText` 落空且**无覆盖率探测/无提示**。篆书路径已有 `useSealOutOfRange` 提示机制，但该机制未覆盖「楷/宋字体缺字」场景。 |
| **影响面** | 输入生僻字的用户；与 BUG-003 同源（生僻字亦触发 404） |

### 🟡 BUG-006 — 长文渲染阻塞且无进度反馈

| 项 | 内容 |
|---|---|
| **严重度** | P3（可用性） |
| **模块** | `src/engine/scene.ts` 预加载分块 · 渲染 |
| **复现步骤** | 1. 新建作品<br>2. 粘贴 5000 个 `永`<br>3. 观察页面响应与渲染完成时间 |
| **预期** | 分块让出主线程，界面保持可交互，并有「正在准备…」提示 |
| **实际** | 渲染完成约 **4030ms**，期间主线程占用高；最终能正确渲染（`ink=12326`），但无进行中反馈 |
| **证据** | `5000 字可渲染不崩溃: 耗时≈4030ms ink=12326`（PASS，但耗时偏高） |
| **根因** | 虽已有 `CHUNK=200` + `setTimeout(0)` 让出机制，但单批 200 字的 `loadStrokeData` 网络并发 + 首帧绘制仍造成明显停顿；无 loading 态。 |
| **影响面** | 长文用户（5000 字为硬上限场景） |
| **备注** | 未达「不可用」程度，列为 P3 观察项 |

## 三、经复核排除的「疑似缺陷」（脚本误报，非产品问题）

| 初判 | 复核结论 |
|---|---|
| 首页无「快速开始」/「全部模板」按钮 | `home.quickStart` / `home.allTemplates` 是**死 i18n 键**（全项目零处 `t()` 调用）；首页实际提供「新建作品 / 我的项目 / 用此模板」，功能完整。**建议清理死键**（非缺陷）。 |
| Tab 首焦点非 skip link | 探测方式错误（`document.body.focus()` 干扰）。改用直接 `Tab` 后实测焦点序：`a.im-skip-link「跳到主内容」→ a.im-logo`，**合规**。 |
| 导出对话框未打开 / 无格式说明 | 选择器误抓「导出工程」按钮。实际点「导出视频」后对话框正常打开，含「推荐格式：MP4（WebM 保底 / MP4 增强，自动降级）」及能力探测，**正常**。 |
| 导出缺分辨率/帧率选项 | 设计如此：分辨率/帧率在右栏「画布」分组统一配置，导出对话框**只读展示**派生值（对话框内 `select` 数=0）。**非缺陷**。 |
| 项目搜索过滤失效 | 搜索框选择器 `input[type=search]` 不匹配（实际为普通 input + placeholder「搜索标题或正文…」）。按 placeholder 定位后过滤正常。**非缺陷**。 |
| 书写分组摘要错误 | 选择器误抓「字体」分组；六组摘要实测均正确。**非缺陷**。 |

## 四、修复优先级建议

1. **立即修复（阻断交付）**：BUG-001（暂停）、BUG-002（数据丢失）——两项均属「核心功能不可用/数据丢失」。
2. **本次一并修复（低成本高收益）**：BUG-003（加 CJK 过滤，1 行判定即可消除 404 泛洪）、BUG-004（`usage` 走 i18n + 扩展校验范围）。
3. **建议修复（体验）**：BUG-005（字体缺字提示，可复用既有越界提示组件）。
4. **观察项**：BUG-006。

## 五、缺陷与既有质量门禁的关系（为何此前未拦截）

| 门禁 | 为何未发现 |
|---|---|
| `check-i18n.mjs` | 仅扫描 `src/pages`、`src/components`，漏掉 `src/lib/licenses.ts` → BUG-004 逃逸 |
| `e2e/release-check.mjs` C5 | 用例均**显式** `Control+s` 后才断言 → BUG-002 逃逸 |
| `e2e/v2c5.mjs` | 未覆盖「暂停后进度是否静止」→ BUG-001 逃逸 |
| 既有 E2E 套件 | 全部使用**常用汉字**或**纯汉字无标点**文本 → BUG-003 逃逸 |
| 单元测试 | `containSize` 数学性质测试通过，但未测「暂停态 rAF 是否仍在跑」→ BUG-001 逃逸 |

> **流程结论**：本次自测暴露的不是「测得不全」，而是**测试文本样本不真实**（不用标点/数字/生僻字）与**只测「确定路径」不测「默认路径」**（只测显式保存、只测常用字）。建议后续 E2E 统一加入「真实文本样本」（含标点/数字/中英混排）与「不保存即离开」用例。
