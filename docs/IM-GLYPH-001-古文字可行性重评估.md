## 2. 评估结论（TL;DR）

| 问题 | MVP 规划期结论 | **本次重评估结论** |
|---|---|---|
| 古文字路径能否在 V1.0 交付？ | 不能（阻塞于字体资产） | **能**，但必须限定为**受限字库模式**（预设字表，非任意文本） |
| 是否必须自研骨架化算法？ | 是（MAT/Zhang-Suen + RDP） | **不必须**。优先直接使用真实篆字字形（含今字映射）；骨架化降级为可选增强/兜底 |
| 主要风险是什么？ | "能否实现"（R&D 风险） | 转为**"字库覆盖率与扩充策略"**（工程/运营风险） |
| 对应原风险 | R-01（高）、R-03（高） | **R-01 可关闭**（依赖已满足）；**R-03 降级**（不再走骨架化主路径） |

> **决策 D-V1-01：** 古文字路径从"骨架化模拟"**转为"受限字库 + 真实字形映射"**。此决策与 IM-BASELINE-001 §1 修正项 1（"古字体改为受限字库"）**方向一致**，且进一步明确：字源已实际可用，不再需要以骨架化作为唯一手段。

## 3. 外部依赖事实核验（2026-10 时点）

> 本节所有事实均经实时检索核验，核验时间：2026-10-13。规划评审时应复核。

### 3.1 Unicode 18.0 小篆独立编码已发布

| 项 | 内容 |
|---|---|
| 发布时间 | **2026-09-16** |
| 新增区块 | **Seal（小篆）U+3D000–U+3FC3F** |
| 码位数 | **11,328** |
| 底本来源 | 《说文解字》四个版本（THX / CCZ / QJZ / DYC） |
| 意义 | 篆字获得**独立于 CJK 统一表意文字**的码位，可按码位直接寻址字形 |

**对工程的影响：** 字形寻址从"按今字推测"改为"按小篆码位直取"，映射关系可**静态化**（今字 → 小篆码位），运行时零推测。

### 3.2 霞鹜篆书 LXGW Seal 已开源（首选字源）

| 项 | 值 |
|---|---|
| 仓库 | github.com/lxgw/LxgwSeal |
| 授权 | **SIL OFL 1.1**（可商用、可嵌入、可再分发；须随附 OFL.txt；保留字体名称"霞鹜 / LXGW"） |
| 当前字数 | **165 篆字**（2026-10-08 扩充节点） |
| 演进轨迹 | 2026-07 首版 45 字 → 2026-10 达 165 字 |
| 映射能力 | 每个篆字设定 Unicode 18.0 小篆码位，**并含对应今字映射**（示例：U+3ECA3 ↔ 獻/献） |
| 正式版计划 | **已缩减为 200 余字**（原规划 300 字），删减二十八宿、八卦等低频字；**正式版完成后不再维护** |

**风险提示：** 该字体**停止维护**是已声明事实。因此 V1.0 必须把"字库可替换"作为架构约束，不能让渲染逻辑与单一字体文件强耦合。

### 3.3 备选字源（用于覆盖率扩展）

| 字体 | 授权 | 字数 | 风格/备注 |
|---|---|---|---|
| 敬峰中山王篆 | OFL | ~2832（简体）/ 2072（繁体） | 战国中山王风格；含《道德经帛书本》《小学必背古诗》覆盖，**内容题材契合度高** |
| 全字库说文解字 | 台湾地区政府资料开放授权（可商用） | 6721 | 说文小篆风格；无标点、无字母 |

**备选接入策略：** 主字源 + 备选字源构成**分层字表**，同一小篆码位只取一个优先字形（优先级：霞鹜 > 敬峰 > 全字库），保证视觉一致性。

### 3.4 MVP 期已核验但**不作为 V1.0 字源**的资源

| 资源 | 原因 |
|---|---|
| CODH 篆書字体数据集 | 提供**字形图像**（13,213 文字种、10 万+ 图像），非可用字体文件；仅作参考底本 |
| 汉语多功能字库 | 提供字形出处索引，非字形素材 |
| 原"开元小篆" | 原规划假设的字体，已被霞鹜篆书等实际可用字源取代（其授权 OSL 1.1 判断依据同时更新为 OFL 1.1 生态） |

## 4. 技术方案：受限字库 + 真实字形映射

### 4.1 数据模型（新增/变更）

```typescript
// 篆字字形条目：一个篆字 = 一个 Unicode 18.0 码位
interface SealGlyph {
  codePoint: number;        // 小篆码位，如 0x3ECA3
  modernChars: string[];    // 对应今字（可能多对一），如 ['獻', '献']
  source: 'lxgw' | 'jfzs' | 'tw-kai-seal';  // 字源标识
  fontFile: string;         // 所属字体文件（子集化产物）
}

// 受限字表：V1.0 古文字路径的可渲染全集
interface SealCharset {
  version: string;          // 字表版本，如 'seal-2026.10'
  glyphs: SealGlyph[];
  modernIndex: Map<string, number>;  // 今字 → 小篆码位（O(1) 查询）
}
```

**与 IM-API-001 §5.1 的兼容性：** 原接口 `checkRestrictedChars(text, font)` 语义不变；古字体选中时 `charset` 从"空（全字库）"变为**返回受限字表**，越界字符仍走 `restricted:chars` 事件与统一提示文案（IM-UI-001 §14.3）。**接口签名无需变更，仅数据来源变更。**

### 4.2 映射策略（三级降级）

```
输入今字
  ├─ 1. 今字直查 modernIndex → 命中则取对应篆字码位，按真实字形渲染
  ├─ 2. 未命中但存在异体/繁体映射（如 献→獻）→ 二次查询后命中
  └─ 3. 仍未命中 → 判定越界：跳过该字 + 触发 restricted:chars + UI 提示
```

**映射正确性保障：**
- 映射表以字体文件自带的 cmap/字表为**唯一真源**，不人工编造。
- 建立**抽样校验集**（如《千字文》前 100 字中在库部分），作为 IM-TEST-V1 §5.2 的验收依据。
- 映射冲突（同一今字对应多个篆字码位）时，取字表声明的主码位，并在字表元数据中记录 `aliases`。

### 4.3 渲染方案

| 层次 | 方案 | 说明 |
|---|---|---|
| 主方案 | **整字显现**（whole glyph） | 使用 `fillText` 直绘小篆字形，配合淡入/描边节奏。与宋体路径共用渲染原语 |
| 增强（可选） | **轮廓描边动画** | 通过字形轮廓点序列做"渐次显现"，非真实笔顺但具书写感。**TBD-V1-02 决策** |
| 兜底（不急做） | 骨架化 | 仅当某字源仅有位图（无字体文件）时才启用；V1.0 不计划投入 |

> **与楷体路径的本质差异：** 楷体有 hanzi-writer 的**真实笔顺数据**（medians 中线）；篆字**没有笔顺数据**。因此古文字路径在 V1.0 **不承诺逐笔书写**，只承诺**整字显现 + 可选描边节奏**。这一点必须在 UI 文案中明确告知，避免用户预期偏差（同时写入 IM-UI-001 帮助页与限制说明）。

### 4.4 与许可证约束的关系

IM-BASELINE-001 §6 红线 2 原为"开元小篆正式发行前不得打包"——**该字体已不是本方案依赖**，故该红线条目应按本文件 §5 更新为对霞鹜篆书/备选字源的 OFL 要求。

| 资源 | 授权 | 落地要求 | 检查位置 |
|---|---|---|---|
| 霞鹜篆书 LXGW Seal | OFL 1.1 | ① 产品内**可见署名**（关于/致谢页）；② 随附 **OFL.txt**；③ 保留字体内部名称，改名需遵守 OFL 保留名称条款 | 发布检查单 V1-C2 |
| 敬峰中山王篆（若接入） | OFL | 同上 | V1-C2 |
| 全字库说文解字（若接入） | 政府资料开放授权 | 依其条款署名（通常要求注明来源机关） | V1-C2 |
| 楷体 / Hanzi Writer 数据 | Arphic PL | 沿用 MVP 已有署名机制，**不因 V1.0 变更** | MVP 检查单 C2 |

**合规红线（V1.0 版）：**
1. 任何被使用的字源，其 OFL.txt / 授权声明必须随**子集化产物**一同分发（子集化不改变授权义务）。
2. 字库文件不得静默替换为来源不明的同名字体；每次升级须记录字源与版本。
3. 越界字符**不得**以其他字体的近似字形"冒充"篆字渲染——宁缺毋滥。

## 6. 覆盖率评估与扩充策略

### 6.1 当前覆盖率（165 字主字源）

| 场景 | 预估覆盖率 | 结论 |
|---|---|---|
| 《千字文》前 100 常用字 | 待抽样（V1-C1 实测） | 抽样数据决定是否需扩展字源 |
| 常见古诗用字 | 偏低（字源以《说文》部首字/常见古字为主） | **需备选字源补充** |
| 用户自由输入 | 很低 | 受限字库模式下**预期内**行为，靠越界提示引导 |

### 6.2 分层扩充策略

```
L0 主字源（霞鹜篆书 165 字）      —— 必装，体积小，视觉统一
L1 内容包（敬峰中山王篆 ~2832 字）—— 按需加载，扩展覆盖率
L2 全字库（全字库说文解字 6721 字）—— 可选加载，最大覆盖（体积大）
```

- 分层以**子集化 + 按需加载**实现（子集工具链见 §7），用户可按需下载内容包。
- 字表 UI（N1.3）需显示"当前可用字数"与"可下载内容包"，把覆盖率透明化。

### 6.3 扩充决策点（对应 TBD-V1-01）

| 选项 | 成本 | 收益 | 建议 |
|---|---|---|---|
| A. 仅霞鹜（165 字） | 最低 | 只能演示，实用性低 | 不推荐单独使用 |
| B. 霞鹜 + 敬峰 | 中（多一个字体文件与映射） | 覆盖《道德经》《小学必背古诗》，题材契合 | **推荐（V1.0 默认）** |
| C. 再加全字库说文解字 | 高（体积/映射成本） | 覆盖率最高 | 作为 L2 可选加载 |

## 7. 子集化与体积控制

| 项 | 措施 |
|---|---|
| 字体文件 | 用 `fonttools`/`pyftsubset` 按字表子集化，仅保留字表内码位 |
| 格式 | 优先 `woff2`（压缩率高，现代浏览器全支持） |
| 加载 | 走既有 `fetchAssetCached` + CDN 版本化路径（`inkmotion-assets-v2`） |
| 体积预估 | 165 字子集 → 数十 KB 级；2832 字子集 → 数百 KB 级；6721 字 → 可能 > 1MB（故作可选） |
| 预算 | 计入 N4.3 性能优化与发布检查单 V1-C10 |

**注：** 子集化**只在构建期进行一次**，产物随静态资源发布；不引入运行时服务端（保持纯前端铁律）。

## 10. 结论与移交

1. **古文字路径在 V1.0 可交付**，形态为"受限字库 + 真实字形映射 + 整字显现（可选轮廓描边）"。
2. **R-01 关闭**（字源依赖已满足）；**R-03 降级**（骨架化不再是主路径，转为可选兜底）。
3. 新风险集中在**覆盖率与字库可持续性**（霞鹜停止维护），已在 IM-RISK-V1-001 登记。
4. 本文件 §9 的 GV-01~GV-06 作为 **V1-C1 的验收前置**，通过后进入 N1.2~N1.4。
5. 需用户就 **TBD-V1-01（字源选型，建议方案 B）** 与 **TBD-V1-02（是否需要轮廓描边动画）** 给出意见。
