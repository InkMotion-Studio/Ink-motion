## 一、方法说明：为什么不能只看「控件在不在」

在此之前，测试的隐含假设是「控件渲染出来 = 功能可用」。这个假设在本项目里**被证伪过两次**：

1. **字体上传**：控件在、上传成功、列表有条目——但渲染链路里根本没有承载字段，
   画布完全不受影响（V2-C4 修复）。
2. **参数滑块**：`Slider` 是**受控组件**，用脚本直接写 `el.value` 会被 React 复原；
   早期 E2E 曾因此得到「参数无效」的假结论，实际是**测试方法错误**。

因此本表对每一项都给出「**可观测证据**」的具体形式，并在证据本身易失真时改用更稳健的观测点
（例如用**同刻进度**而非绝对时长判断速度，用**墨迹像素面积**而非哈希判断字号）。

## 三、界面合理性自查（对应「布局是否合理？」）

### 3.1 修复前的问题

| 问题 | 症状 | 根因 |
|---|---|---|
| 预览比例写死 | `aspect-ratio: 9/16` + `max-width: 360px` | 横屏 16:9 画布被强塞进竖屏框；大屏下预览过小、大片留白浪费 |
| 中栏不居中 | `grid-template-columns: 320px 1fr 300px`（左右不等宽） | 中栏几何中心偏离视口中心 |
| 参数面板过长 | 6 个 `fieldset` 全部平铺展开 | 320px 窄栏下需长距离滚动，找不到目标项 |
| 受限字库提示占地 | 篆书/隶书字库面板常驻展开 | 与参数混排，挤压真正高频的调控项 |
| 折叠缺失 | 左右栏不可收起 | 专注预览时无法腾出空间 |

### 3.2 修复后

| 项 | 处理 |
|---|---|
| 预览缩放 | `useElementSize` 实测容器 + `containSize()` 按**画布真实宽高比**等比内接，`place-items: center` 居中；`data-ratio` 暴露真实比例 |
| 三栏比例 | `320px | 1fr | 320px`，≥1440 放宽至 `360 | 1fr | 360`，1200–1440 收至 `288 | 1fr | 288` |
| 参数折叠 | 6 组全部改 `Collapsible` 手风琴，**标题右侧显示当前取值摘要**（收起也可读） |
| 受限提示 | 内联进「字体」分组低位，不再独立占块 |
| 左右折叠 | 支持收起为 56px 竖排窄轨；**栅格真实重排**（中栏吃掉释放空间），状态持久化 |
| 断点 | 1440 / 1200 / 900 三档，≤1200 预览置顶两栏，≤900 单栏堆叠 |

### 3.3 一个刻意的工程取舍

`Collapsible` 收起时用 `hidden` 而非条件渲染卸载子树。原因：`Select`/`Slider` 一旦卸载，
其 DOM 状态与焦点会丢失，重新展开可能出现取值回跳。E2E 已就这一点设专门断言
（「折叠参数分组不重置已选值」）。

## 四、过程中发现并修复的产品缺陷

### 4.1 暂停态下参数变化不可见（重要）

**现象**：在预览暂停（或已播完）时调整参数，场景会按新参数重建并从 `t=0` 重绘，
但重建后的重绘只发生一次 → 画布停留在「刚起步」的一帧，**看起来参数没生效**。

**影响**：这正是用户体感「改了没用」的同类问题——功能是好的，但界面没把结果呈现出来。

**修复**：在 `PreviewCanvas` 中新增「缓动重绘」副作用——场景切换后按真实时间轴持续重绘至结束
（`ease()` + `requestAnimationFrame`），保证观感与实测都反映最新参数。

**证据**：修复后第 6 项从「3794 vs 15643（差异被首帧掩盖）」变为
「3794 vs 43553（真实且单调的墨迹增长）」。
