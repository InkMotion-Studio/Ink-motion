## 2. 引言

### 2.1 目的

本文档识别、评估并跟踪"墨演 InkMotion"在 MVP/V1.0/V2.0 落地过程中的关键风险，提供应对策略与跟踪机制，确保在风险演变为阻塞前被发现和缓解。

### 2.2 风险分类

| 类别 | 说明 |
|---|---|
| 技术 | 算法/库/浏览器能力不确定性 |
| 资产 | 设计/字体/纹理资源交付或授权 |
| 合规 | 开源许可署名与分发 |
| 市场 | 可触达人群、传播口径 |
| 进度 | 排期、人员、依赖 |
| 质量 | 性能、兼容性、无障碍 |

## 3. 风险矩阵

| 影响 \ 概率 | 低 | 中 | 高 |
|---|---|---|---|
| **高** | 监控类 | R-03 骨架化质量、R-01 字体源阻塞 | — |
| **中** | R-11 第三方库 | R-02 浏览器兼容、R-04 首屏体积、R-05 性能、R-06 许可、R-07 资产阻塞、R-08 人群、R-10 导出兼容 | R-09 覆盖率/体积 |
| **低** | R-12 排期 | — | — |

等级定义：
- **高**：可能导致阶段回退或范围削减。
- **中**：可导致延期或质量降级，需主动缓解。
- **低**：影响可控，常规应对。

## 4. 风险登记册

### R-01 开源小篆字体未发布（古文字路径阻塞）`[资产/技术·高]`

| 项 | 内容 |
|---|---|
| 描述 | 开元小篆 = OFL 1.1，但**尚未发布**（11,328 码位、校对中）；隶书源"待定"。古文字（小篆/隶书）骨架化路径依赖字体源。 |
| 影响 | V1.0 古文字路径无法落地，N2.3 阻塞。 |
| 概率 | 高（已确认未发布） |
| 应对 | ① 将 N2.3 标注 [V1.0，阻塞：字体资产]（IM-PLAN-001 §5.3）；② 跟踪开源小篆发布进度（每迭代）；③ 若到期未发布，古文字整体推 V2.0，MVP 仅保留楷体+宋体；④ 隶书同步寻源或砍掉。 |
| 触发条件 | 进入阶段 2 前未确认字体源可用。 |
| 负责人 | 技术负责人 |
| 跟踪 | RK-0 周度复盘 |

### R-02 浏览器 WebCodecs 兼容性缺口 `[技术·中]`

| 项 | 内容 |
|---|---|
| 描述 | WebCodecs H.264 不在 Firefox（含 Android）支持；Safari 26+ 才完整支持。MP4 主路径在部分浏览器不可达。 |
| 影响 | 导出格式按浏览器分化，用户预期管理复杂。 |
| 概率 | 高（已知事实） |
| 应对 | 自动降级（IM-API-001 §4.4.3）；WebM 保底覆盖 Firefox；引导式文案而非拒绝式（IM-UI-001 R1 已修正）。 |
| 触发条件 | 导出时检测 `VideoEncoder` 可用性。 |
| 负责人 | 导出引擎负责人 |
| 跟踪 | 兼容性测试 N4.4 |

### R-03 骨架化质量不达标 `[技术·高]`

| 项 | 内容 |
|---|---|
| 描述 | 小篆/隶书位图经 MAT/Zhang-Suen+RDP 生成的笔锋路径可能"不可看"，是真正的 R&D 风险。 |
| 影响 | 古文字路径体验失败，需推后或重做。 |
| 概率 | 中 |
| 应对 | 阶段 2 前置时间盒 Spike（IM-PLAN-001 §6）；肉眼评估标准；不达标即降级为整字显现或推 V2.0。 |
| 触发条件 | Spike 输出质量评审未过。 |
| 负责人 | 图形工程师 |
| 跟踪 | M1 引擎 Demo 闸门 |

### R-04 首屏体积过载 `[技术/质量·中]`

| 项 | 内容 |
|---|---|
| 描述 | CJK 字体 + Hanzi Writer 逐字 stroke 数据 + 纹理，纯前端首屏很重。 |
| 影响 | 加载慢、首屏体验差、移动端不可用。 |
| 概率 | 中 |
| 应对 | 代码分割、字体子集化（IM-DB-001 TBD-DB-01）、资产走 CDN 并缓存版本化（IM-DB-001 §6.3）、按需加载笔画数据。 |
| 触发条件 | 首屏体积超预算（N4.3 性能优化）。 |
| 负责人 | 前端架构 |
| 跟踪 | 性能测试 N4.3 |

### R-05 5000 字全量逐笔性能压力 `[技术/质量·中]`

| 项 | 内容 |
|---|---|
| 描述 | 5000 字全量逐笔动画对 Canvas2D 压力极大；硬上限保留但体验上限需另定。 |
| 影响 | 长文本预览卡顿、导出超时。 |
| 概率 | 中 |
| 应对 | 分块渲染/降帧、虚拟滚动、体验上限单独定（如 ≤1000 字流畅，超出降质）；规格 5000 作硬上限。 |
| 触发条件 | 性能预算不达标（IM-DB-001 §10.5）。 |
| 负责人 | 前端架构 |
| 跟踪 | 性能测试 N4.3 |

### R-06 开源许可署名遗漏 `[合规·中]`

| 项 | 内容 |
|---|---|
| 描述 | Arphic PL（楷体）须**可见署名**；OFL（宋体 Source Han Serif、开源小篆）须署名且随分发。遗漏即违约。 |
| 影响 | 许可违约，项目法律风险。 |
| 概率 | 中（易遗漏） |
| 应对 | 关于/致谢页固化（IM-UI-001 §6.5.1）；列入 MVP 发布检查单 C2（IM-PLAN-001 §9）；N1.4 建立许可基线。 |
| 触发条件 | 发布前检查单核对。 |
| 负责人 | 技术负责人 |
| 跟踪 | N1.4、N5.3 检查单 |

### R-07 设计/贴图资产阻塞 `[资产·中]`

| 项 | 内容 |
|---|---|
| 描述 | Figma TBD（Logo、载体贴图、空状态插图、组件同步）阻塞 N1.1；贴图阻塞 N2.5。 |
| 影响 | 阶段 1/2 关键路径延期。 |
| 概率 | 中 |
| 应对 | M0 前锁定设计交付排期（TBD-PLAN-02）；N1.1 先交付 Token 与核心组件，贴图用占位资源并行开发。 |
| 触发条件 | M0 末 Figma 资产未到位。 |
| 负责人 | 设计 + 前端 |
| 跟踪 | RK-0 |

### R-08 可触达人群受限 `[市场·中]`

| 项 | 内容 |
|---|---|
| 描述 | MP4 需 Chromium 或 Safari 26+（很新）；MVP 主要触达桌面 Chromium + 较新 Apple 设备。 |
| 影响 | 传播与用户获取受限。 |
| 概率 | 高（事实） |
| 应对 | 传播口径务实；优先桌面；移动端预览可用、导出 V1.0+ 评估（IM-UI-001 §9.4）。 |
| 触发条件 | 市场推广期。 |
| 负责人 | 产品 |
| 跟踪 | 发布后复盘 |

### R-09 Hanzi Writer 覆盖率与数据体积 `[技术·中-高]`

| 项 | 内容 |
|---|---|
| 描述 | 用户文本任意 ≤5000 字，需验证常用诗词/古文覆盖率；逐字 stroke JSON 体积不小。 |
| 影响 | 缺失字需降级；包体增大。 |
| 概率 | 中 |
| 应对 | Spike 抽样验证；缺失字整字显现降级（MVP 即用）；数据按字库 CDN 托管（IM-DB-001 §6.3）。 |
| 触发条件 | Spike（IM-PLAN-001 §6）。 |
| 负责人 | 笔画引擎负责人 |
| 跟踪 | M1 闸门 |

### R-10 导出容器兼容性细节（Safari WebM 弱支持） `[技术·中-高]`

| 项 | 内容 |
|---|---|
| 描述 | Safari 对 WebM 编码支持弱（Safari MediaRecorder 实际输出 MP4/H.264）；Chromium 出 WebM、Firefox 出 WebM。降级矩阵需按"编码器 + 容器"双维度决策，而非简单 WebM/MP4 二分。 |
| 影响 | 误以为 WebM 全浏览器保底，Safari 实际走 MP4 分支。 |
| 概率 | 中 |
| 应对 | 导出决策矩阵：**WebCodecs H.264 MP4**（Chromium / Safari 26+ 首选）→ **MediaRecorder**（Chromium 出 WebM；Safari 出 MP4；Firefox 出 WebM）。Firefox 全系无 WebCodecs 走 WebM。明确"WebM 主要覆盖 Firefox"，Safari 靠 MP4。 |
| 触发条件 | 导出实现与测试（IM-TEST-001 §5.1）。 |
| 负责人 | 导出引擎负责人 |
| 跟踪 | N4.4 兼容性测试 |

### R-11 第三方库依赖 `[技术·低]`

| 项 | 内容 |
|---|---|
| 描述 | Hanzi Writer、Dexie、Lucide Icons 等第三方库的维护状态与许可（均宽松许可，风险低）。 |
| 影响 | 低；主要为维护成本。 |
| 概率 | 低 |
| 应对 | 锁版本、记录 SBOM；Lucide（MIT）、Dexie（MIT）、Hanzi Writer（MIT/Arphic PL 数据）分别合规。 |
| 触发条件 | 依赖审计。 |
| 负责人 | 前端架构 |
| 跟踪 | 每迭代 |

### R-12 排期与人员风险 `[进度·低]`

| 项 | 内容 |
|---|---|
| 描述 | MVP ≈ 18–22 周（1.5–2 人）；人员变动或设计/资产延期会拉长。 |
| 影响 | 延期。 |
| 概率 | 低-中 |
| 应对 | RK-0 周度复盘；关键路径（N1.1/N2.5/N2.6/N3.3）优先保障；阶段门禁（M0–M4）防范围蔓延。 |
| 触发条件 | 里程碑延期超 1 周。 |
| 负责人 | 技术负责人 |
| 跟踪 | RK-0 |
