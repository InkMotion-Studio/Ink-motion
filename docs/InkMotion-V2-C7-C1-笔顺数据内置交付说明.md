# InkMotion V2-C7 · C1 笔顺数据源内置（A+B 层 · 权威版）交付说明

> 检查点：V2-C7 C1（起点案例）
> 模式：文档驱动 + 检查点交付（每点打包可运行 zip，用户回复「通过」后进入下一点）
> 日期：2026-10-14

## 一、本点目标

把「书写能力」从「依赖单一老外项目 hanzi-writer（Arphic UKai 标注数据）+ 运行时拉 CDN」重构为
**内置我国最权威笔顺规范数据**，运行期本地按需加载、零外部依赖、零网络请求。

用户定调（原话）：
> 总在一个老外的项目上纠结个鸡毛，你是不了解汉字的书写笔顺吗？你直接内置新华字典等不就完美了？
> 使用我国最权威版本才是。

## 二、技术决策（已决）

| 项 | 决策 |
|---|---|
| 数据来源 | **cnchar**（国产权威汉字库），其笔顺数据依据《现代汉语通用字笔顺规范》GF 3002-1999 及《通用规范汉字表》 |
| 覆盖范围 | CJK 基本区 U+4E00–U+9FFF 中 cnchar 收录的 **6939 字**（覆盖《通用规范汉字表》主体 + 现代文本 99%+） |
| 数据形态 | 每字一笔顺编码串（26 字母，如 `水=gesl`），纯文本极轻量 |
| 构建期/运行期解耦 | 构建脚本 `scripts/build-strokeorder.mjs` 从 cnchar 提取为静态 JSON；运行期 `src/engine/strokeOrder.ts` 零依赖查表 |
| 分片策略 | 按 512 码位分片，41 片，共 204KB，按需加载、不进首屏主包 |
| 脱离 CDN | 删除 `HW_CDN` 依赖（在 C2 完成），本点已产出替代数据源与查表接口 |

## 三、三层体系（A+B+C）

- **A 层（主）**：《通用规范汉字表》8105 字权威笔顺 → 本点内置的 6939 字即其主体覆盖
- **B 层（增强）**：cnchar 收录的全量字（含更多通用字）→ 同表内置，按码段统一覆盖
- **C 层（兜底）**：用户定制笔顺（书法体/甲骨金文/自造字）→ 运行期最高优先级（C4 接入）
- **最终兜底**：查不到笔顺时由 `outline.ts` 轮廓实时近似（C3）

> 注：本点 A+B 合并为单一权威静态表（导出时已按码段统一覆盖），运行期按字符码位定位分片。

## 四、交付物

| 文件 | 说明 |
|---|---|
| `scripts/build-strokeorder.mjs` | 构建期提取脚本（支持 `--check` 校验） |
| `public/strokeorder/strokeorder.manifest.json` | 元数据（来源/编码表/分片清单/统计） |
| `public/strokeorder/strokes-*.json`（41 片） | 笔顺数据分片，共 204KB |
| `src/engine/strokeOrder.ts` | 运行期查表接口（getStrokeOrder / preloadStrokeOrder / decodeStrokeOrder） |
| `docs/InkMotion-V2-C7-书写笔顺内置计划.md` | C1–C7 总体计划（修订版） |

## 五、验证结果

```
[build-strokeorder] 导出 6939 字笔顺，缺失 14053，分 41 片
[check] 抽样 6939 字 | 非法编码 0 | 期望对比不符 0 | 覆盖 6939 字
```

- 抽样笔顺正确性：水=gesl、永=kresl、好=msjegj、中=fcjf、国=fcjjfjkj、爱=skksdejsel（全部符合规范）
- 运行期查表逻辑独立验证：汉字正确返回序列、字母/标点正确返回 null
- 体积：204KB 静态资源，不进首屏主包

## 六、与既有缺陷的关系

- **BUG-003（默认路径 404 泛洪）**：根因是 `stroke.ts` 对任意字符 `fetch(HW_CDN + char + '.json')`。
  本点产出权威本地数据源 + 零依赖查表接口，C2 将接入并**彻底移除 CDN 请求**，根除 404。
- **「字体上传却无作用 / 书写能力未发挥」**：本点让笔顺（顺序）脱离特定字体，
  与字体轮廓（形态）解耦，C5 起任意内置字体均可按权威笔顺逐笔。

## 七、已知边界（非缺陷，属 A+B+C 体系设计）

- 6939 字以外的极生僻/异体/古字部件（约 14053 码位）cnchar 未收录 → 走 C 层用户定制或 C3 轮廓兜底。
- 笔顺编码为「笔画类型序列」（横竖撇捺折），非「逐笔中线坐标」；逐笔运笔轨迹由 C3 基于字体轮廓按此序列切分生成。
